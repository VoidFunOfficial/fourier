# Mac mini 宣传片设计风格

这支视频采用苹果官网取向的极简产品 MG：以银色铝合金产品、纸白背景和石墨黑文字建立主体视觉，结合几何组装、连续运镜、官网场景素材与少量手绘笔触。画面保持清楚、疏朗，运动则快速、有力度。高级感来自准确的产品形态、克制的光照、明确的视觉重心和连贯的转场。

本文依据当前 `ad-apple` 工程与 `output/Mac-mini-M6-1080p60.mp4` 的画面整理，包含逐笔画及音效修订。以下数值是本片的实现参考；迁移到其他产品时，保留设计方法，重新适配内容和比例。

## 1. 整体气质

- **精密、安静的视觉外观。** 银色金属、柔和反射、圆角几何、低饱和色彩、大面积留白。
- **快速、明确的运动表达。** 推近、拉远、旋转、展开、吸附、收拢和快速切换共同组织节奏。
- **真实产品与抽象图形穿插。** 产品负责可信度，图形负责解释核心、内存、带宽等难以直接拍摄的信息。
- **手绘承担具体作用。** 勾勒轮廓、标注尺寸、指示接口、表现无线信号，最后用手写字收尾。
- **画面直接呈现卖点。** 产品、数字、几何变化和实际使用场景承担叙事，每个分镜集中表达一个主要信息。

## 2. 配色与光照

| 色彩 | 色值 | 用途 |
| --- | --- | --- |
| 纸白 | `#f5f5f7` | 主背景，贯穿产品展示、参数图解和结尾 |
| 纯白 | `#ffffff` | 高光、局部亮面及深色场景中的文字 |
| 石墨黑 | `#1d1d1f` | 主文字、手绘墨迹、芯片和深色场景 |
| 中灰 | `#86868b` | 次要说明、弱化的信息层级 |
| 铝银 | `#c9cbcf` | 金属感、核心块、内存片层 |
| 浅灰 | `#e8e8ed` | 层次区分及柔和几何底色 |
| 淡桃 | `#efb69c` | 创意内容、媒体条带的小面积点缀 |
| 淡绿 | `#bdd2be` | 创意素材中的辅助色 |
| 雾蓝 | `#b4c9dc` | 媒体内容和气流表达的辅助色 |

白、黑、银构成主色关系。CPU、带宽等少量深色场景形成明暗节奏。辅助色随内容出现，官网素材可以保留自身的屏幕色彩、桌面配色和真实环境。

产品采用中性棚拍光：大面积柔光勾出铝合金转折，边缘有清楚但柔和的明暗变化，底部用轻薄投影交代悬浮高度。保留材质本身的反射和阴影；背景以平整色面为主。避免把银色产品渲染成镜面铬金属，也避免装饰性的蓝紫霓虹、彩色泛光和重暗角。

## 3. 字体、文案与信息层级

英文、数字以 Apple San Francisco 为主，中文使用本地黑体，延续苹果界面字体的简洁感。常规文字以中等字重为主，字距略紧，信息呈现直接。

| 层级 | 本片常见尺度，基于 1920 × 1080 | 表达方式 |
| --- | --- | --- |
| 核心数字／产品关键词 | 约 110–230 px | 一个数字或短语成为当前画面的视觉重心 |
| 功能名称／主要标注 | 约 48–72 px | 与对应产品、接口或图形直接关联 |
| 次要解释 | 约 35–48 px | 简短、少行，必要时用中灰弱化 |
| 条件说明 | 约 21 px | 靠近底部，保留阅读空间 |

常用紧字距约为 `-0.035em` 至 `-0.055em`，短句行高约为 `1.1–1.15`。字体尺度服从构图，不能把所有信息都放大。

“12 核 CPU”“32GB”“170 GB/s”这类文字就是卖点本身，可以大字出现。避免额外添加“极致性能”“未来已来”之类与画面重复的章节标题、小标题或宣传套话。数字到达最终值后要稳定停留，让观众看清数值与单位。

## 4. 构图与几何语言

画幅为 **16:9，1920 × 1080，60 fps**。本片约 75 秒，包含 20 个独立分镜，多数为 3–4 秒，整体范围为 2–5 秒。

构图有四种主要形式：

1. **居中的产品主镜头。** 产品占据核心区域，四周留白；旋转、俯视、底视和局部特写改变观察方式。
2. **文字与图形左右对照。** 一侧呈现数字或功能，另一侧用核心阵列、金属雕塑、内存片层解释内容。
3. **整齐排列的同类对象。** 用阵列、堆叠、条带表达数量、并行和容量，间距与尺度有清楚秩序。
4. **官网图片主导的场景。** 显示器、桌面和应用内容占据大部分画幅，仅保留少量直接标注。

常规文字参考安全边距为左右 110 px、上下 80 px；宏观特写允许产品有目的地越出画面。

**圆角方形是贯穿全片的主要形状。** Mac mini 外壳、芯片封装、核心块、媒体画面和显示器区域共享相近的几何语言。圆角与矩形服务产品内容，避免给每个卖点套上同一种卡片外框。

## 5. 产品模型与官网素材

产品轮廓、厚度、圆角、接口开孔、底部结构及标志必须准确。本片使用苹果公开 AR 模型转换出的几何与原始纹理，镜头依次展示外壳、顶部、正面接口、背面接口和底部。

官网素材承担真实使用情境：创作画面、显示器、散热示意、iPhone 镜像、本地 AI，以及不同工作类型的桌面。素材需要参与运动和构图：裁切、拉近、展开、横向接续，或嵌入显示器与媒体条带。

复用这种风格时，应先选能准确表达当前卖点的官方素材，再决定运镜和图形。素材中的产品颜色、尺寸关系、光线与自建场景保持一致。

## 6. 动效与镜头衔接

每个分镜遵循“进入 → 变化／解释 → 短暂停留 → 带动下一镜”的节奏。速度集中在进场、形变和离场，重点信息出现时给出稳定阅读窗口。

本片常用的运动方式包括：

- 大幅缩放配合轻微旋转，从特写退到完整构图，再向下一个结构推近。
- 核心块和片层以几十毫秒的错位陆续出现，形成组装感。
- 图形在收拢、拉伸或转向时，把已有动势传递给下一镜。
- 文字以小幅上移和透明度变化进入，与主体动作配合。
- 摄像机沿产品外部环绕，近景、俯视与背面镜头有明确观察目的。

常见进场缓动为 `cubic-bezier(.22,1,.36,1)`，表现快速到位后的柔和减速；部分离场使用 `cubic-bezier(.7,0,.9,.3)`，让动作在结束前加速。匀速数据流和逐笔书写使用线性时间。避免所有元素同时弹跳，或在观众读字时持续晃动。

衔接优先寻找形状、位置和方向的联系。例如，产品俯视的圆角方形缩成芯片，芯片展开成核心阵列，内存片层拉长成为数据通道，数据通道接续为媒体条带。需要切换视觉空间时，可用放大、遮挡或匹配剪切完成接续。

## 7. 手绘与指示线

手绘风格保持朴素、准确：圆头、圆角、轻微自然弯曲，局部有细小的不规则感。线条指向明确对象，避免随意涂鸦和持续抖动。

**产品指示线短、粗、干净。** 正背面接口的标注约为 **6 px 粗、64–77 px 长**，圆端处理。尺寸标注用分开的短端点和文字组成，减少贯穿整个产品的长线。普通轮廓、连接路径可使用较细线宽；无线信号等承担主体造型的符号可以更粗。

线条出现应有绘制方向和时间过程，与对应物体或文字的到位动作配合。

## 8. 结尾的三个节拍

| 时间 | 内容 | 风格作用 |
| --- | --- | --- |
| 62–66 s | Productivity → Creativity → STEM → Gaming → Coding | 用快速变化呈现多种用途，同时保留固定的产品视觉锚点 |
| 66–71 s | 手写 `ALL IN` / `MAC mini` | 从密集的信息切换收束到简洁、有手感的品牌记忆 |
| 71–75 s | `this video` / `完全由 Fourier Harness + GPT6` / `独立完成` | 用居中排版、轻微入场与停留完成署名 |

用途切换约 **每 0.7 秒一次**。桌面、周边和应用画面变化时，Mac mini 的位置、比例、角度与外观保持不变；最后一个用途稍作停留。固定机身让快速切换依然有稳定的观看重心。

手写结尾采用石墨黑墨迹、纸白背景和两行居中构图，保留大量空白。字形略带倾斜，笔端圆润。当前版本将文字拆成 **29 条独立笔画**，按真实落笔、行笔、抬笔的顺序绘制，A 的横杠与小写 i 的点各自出现。书写约在这一镜的第 4 秒完成，剩余约 1 秒定格。实现时沿笔画路径推进，避免整行文字从左到右的矩形擦除式显现。

## 9. 音效风格

本片使用音效，不加入 BGM。声音跟随具体动作，形成快节奏中的力度、触感与空间变化。

| 画面动作 | 声音表达 |
| --- | --- |
| 产品转动、推拉与转场 | 短促气流、轻扫和位移声 |
| 芯片、阵列、内存组装 | 干净的轻击、卡扣及快速衰减的机械低频 |
| 数据流与媒体条带 | 轻快、短小的划过声和细碎触发声 |
| 接口和尺寸标注 | 低存在感的点击与落位声 |
| 五种用途切换 | 与切点对齐的短扫动、轻弹响 |
| 手写结尾 | 真实笔尖摩擦声，每一笔独立起止，抬笔留白 |

声像可随画面横向移动，尾音保持短，避免声音堆积。书写声的起止与笔画共用时间数据；最终墨迹停留时，笔声也停止。

## 10. 复用时的执行准则

先确定每一镜要表达的内容，再为它选择产品视角、官方素材或几何图解。用少量共同形状贯穿全片，在分镜交界处延续位置、尺度或运动方向。保持中性色主导，让数字清楚、产品准确、动作利落，手绘只出现在能帮助解释或收尾的地方。

应保留：大留白、准确产品、柔和金属光照、紧凑字体、圆角几何、短粗标注、快速组装、匹配衔接、固定主体切换和真实逐笔书写。

应避免：无关标题、说明文字堆满屏幕、固定卡片模板、通篇装饰边框、彩色霓虹背景、强烈镜头抖动、泛用故障效果、无目的粒子、反复全屏淡入淡出，以及音效与动作脱节。

在 Fourier 中按 `Scene → Component → Motion → Render` 实现：每个 Scene 表达一个完整信息，复用公共组件，由本镜头管理自己的动作，根工程负责组合。制作方法与视觉风格共同保证后续修改仍能保持一致。
